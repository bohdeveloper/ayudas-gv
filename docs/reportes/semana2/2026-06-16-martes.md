# Reporte diario — Martes 16/06/2026

## ✅ Completado

### Spring Security: cadena de filtros stateless

- `SecurityConfig.java` reescrito con `SecurityFilterChain` completo para JWT:
  - `csrf(AbstractHttpConfigurer::disable)` — sin cookies de sesión, CSRF no aplica
  - `sessionManagement(STATELESS)` — Spring no crea ni usa `HttpSession`; cada petición es independiente
  - `authorizeHttpRequests`: rutas públicas (`/v1/auth/login`, `/v3/api-docs/**`, `/swagger-ui/**`) con `permitAll()`; el resto con `authenticated()`
  - `exceptionHandling.authenticationEntryPoint` personalizado: devuelve 401 (no 403) en peticiones sin autenticar
- Estudiada la diferencia entre 401 (no autenticado) y 403 (sin permisos suficientes)
  - Spring Security 6 devuelve 403 por defecto para peticiones anónimas
  - El `authenticationEntryPoint` corrige esto para devolver 401 cuando no hay autenticación

### BCrypt y verificación de contraseñas

- `@Bean PasswordEncoder` registrado como `BCryptPasswordEncoder(10)` en `SecurityConfig`
- Estudiado el funcionamiento de BCrypt: salt automático incluido en el hash, factor de coste `2^10` iteraciones
- `passwordEncoder.matches(plainText, hash)` verifica la contraseña sin exponerla ni re-hashear
- Verificado: el mismo texto plano con `encode()` genera hashes distintos cada vez (salt diferente), pero `matches()` siempre devuelve `true` para el texto correcto
