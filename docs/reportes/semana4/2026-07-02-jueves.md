# Reporte diario — Jueves 02/07/2026

## Completado

### Paginación y ordenación verificadas

- `GET /v1/expedientes?size=2&sort=numeroExpediente,asc` → 2 resultados, `totalPages: 3`, orden ascendente por número de expediente correcto
- Formato de `sort` validado: `campo,asc|desc`; si el campo no está en la lista blanca (`SORT_COLUMNS`) se ignora sin error y se aplica el valor por defecto — probado con un campo inventado, no rompe la consulta
- `LIMIT`/`OFFSET` calculados en `ExpedienteRepository.buscar()` a partir de `page`/`size` ya normalizados por el servicio

### Traducción de catálogos por `Accept-Language`

- `GET /v1/expedientes` con `Accept-Language: es` → descripciones en castellano ("Asignación económica por hijo o menor a cargo con discapacidad", "Registrado"...)
- Misma petición con `Accept-Language: eu` → descripciones en euskera ("Desgaitasuna duen seme-alaba edo ardurapeko adingaberako diru-laguntza", "Erregistratuta"...) — la columna `descripcion_eu`/`descripcion_es` se resuelve correctamente según el `Locale`

### Frontend preparado para consumir el endpoint

- `axiosClient.ts`: el interceptor de petición ahora añade también la cabecera `Accept-Language` con el idioma activo de `i18next` (`i18n.language`) — **necesario** para que el backend traduzca los catálogos; antes del cambio esta cabecera nunca se enviaba
- `frontend/src/api/expedientesApi.ts`: función `buscarExpedientes(filtros)` — `GET /expedientes` con los filtros como query params, tipado con `ExpedienteFiltros` y `PageResponse<ExpedienteResumen>` (tipos ya existentes desde Semana 1, sin cambios)
- Añadidas las claves i18n que faltaban en `es.json`/`eu.json`: `expedientes.estados.*` (para las opciones del filtro de estado) y `common.previous`/`common.next`/`common.all`
