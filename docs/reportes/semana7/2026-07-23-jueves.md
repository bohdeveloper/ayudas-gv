### `.dockerignore` para backend y frontend (preparación del Bloque 1)

- Antes de construir las imágenes `:1.0` dentro de minikube conviene reducir el contexto de build. Ninguno
  de los dos servicios tenía `.dockerignore`, así que cada `docker build` subía artefactos innecesarios al
  demonio (crítico en el frontend, cuyo Dockerfile hace `COPY . .` y arrastraba `node_modules/` entero)
- `backend/.dockerignore`: excluye `target/`, wrapper de Maven, IDE y metadatos. El multi-stage solo necesita
  `pom.xml` + `src/`
- `frontend/.dockerignore`: excluye `node_modules/` (lo regenera `npm ci`), `dist/`, `coverage/` y `.env*`.
  **No** excluye `nginx.conf` (lo copia la etapa 2), `index.html`, `package*.json`, `src/`, `public/`,
  `tsconfig*.json` ni `vite.config.ts`, que sí necesita `npm run build`
- Verificado con build real de ambas imágenes: el contexto transferido baja a **102,83 kB** (backend) y
  **31,05 kB** (frontend); antes el frontend enviaba `node_modules/` completo. Ambos builds completan sin
  errores (confirma que no se excluyó nada necesario). Imágenes de prueba `:ci-test` eliminadas tras verificar
