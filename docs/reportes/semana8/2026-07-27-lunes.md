  que casca → kubelet reinicia (mismo Pod, `RESTARTS`+1) vs Pod borrado → ReplicaSet crea otro (nombre e IP nuevos)

### Hallazgo del experimento con postgres (falló distinto a lo previsto)

Previsión: el segundo Postgres se negaría a arrancar por el lock `postmaster.pid`. **Realidad: arrancó**, y la
cadena de consecuencias resultó más instructiva que el resultado esperado:

1. `ReadWriteOnce` limita por **nodo, no por Pod** — en un solo nodo de minikube ambos Pods montaron el mismo PVC
2. Cada contenedor tiene su **propio namespace de PIDs**: el 2.º postmaster (también PID 1) leyó el
   `postmaster.pid` ajeno, vio su propio número, lo tomó por un lock huérfano suyo, lo borró y arrancó.
   **El aislamiento de contenedores anuló la protección de Postgres**
3. ~76 segundos con **dos postmasters sobre el mismo directorio de datos** (la ventana de corrupción real)
4. Al bajar a 1 réplica, el Pod 2 borró el lock al salir → el original: `could not open file "postmaster.pid"` +
   `performing immediate shutdown because data directory lock file is invalid` → `RESTARTS 2` y recuperación WAL
5. **Base de datos íntegra**: Flyway V1–V5 `success=true`, 3 usuarios / 4 roles / 3 tipos de ayuda / 16 auditoría,
   login e2e HTTP 200

Conclusiones registradas: `accessModes: ["ReadWriteOncePod"]` sí lo impediría; un StatefulSet resuelve identidad
y disco por Pod (`volumeClaimTemplates`) pero **no da replicación de Postgres** — eso es un operador
(CloudNativePG, Zalando) o una BD gestionada. Para este proyecto, 1 réplica sigue siendo la respuesta correcta.

## Notas de entorno

- El Ingress **no es alcanzable desde Windows** con el driver `docker` (`curl` a `192.168.49.2` → HTTP 000).
  No es un fallo del clúster: la IP del nodo no se enruta desde el host. Para verlo por navegador hace falta
  `minikube tunnel` en otra terminal. Las pruebas se hicieron desde dentro del clúster, que además es donde se
  observa el balanceo del Service
- El `docker` del PATH en Git Bash es un shim roto (`bad interpreter`). Alternativas usadas: `minikube image ls`
  y `minikube image build`, que no necesitan `docker-env`
