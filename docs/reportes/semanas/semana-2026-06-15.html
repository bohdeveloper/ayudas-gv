Martes 2026-06-16

✅ Completado

Spring Security: cadena de filtros stateless

  • SecurityConfig.java reescrito con SecurityFilterChain para JWT
  • csrf(AbstractHttpConfigurer::disable) — sin cookies de sesión, CSRF no aplica
  • sessionManagement(STATELESS) — Spring no crea ni usa HttpSession; el estado vive en el JWT
  • authorizeHttpRequests: rutas públicas con permitAll(), el resto con authenticated()
  • exceptionHandling.authenticationEntryPoint: devuelve 401 (no 403) en peticiones sin autenticar
  • Estudiada la diferencia entre 401 (no autenticado) y 403 (sin permisos): Spring Security 6 devuelve 403 por defecto para peticiones anónimas; el authenticationEntryPoint corrige esto

BCrypt y verificación de contraseñas

  • @Bean PasswordEncoder registrado como BCryptPasswordEncoder(10) — strength 10 = 2^10 iteraciones
  • BCrypt incluye el salt en el propio hash: el mismo texto plano genera hashes distintos cada vez
  • passwordEncoder.matches(plainText, hash) extrae el salt del hash y verifica — nunca expone la contraseña
  • AuthService parcialmente implementado: usa matches() para validar credenciales

Miércoles 2026-06-17

✅ Completado

Implementación de JwtProvider

  • JwtProvider.java con librería jjwt 0.12.5 (io.jsonwebtoken)
  • Algoritmo HS384 (HMAC-SHA384): firma simétrica, la misma clave secreta firma y verifica
  • HS384 vs HS256: mayor seguridad sin necesidad de clave asimétrica; RS256 si hubiera verificación externa
  • Clave criptográfica desde app.jwt.secret con Keys.hmacShaKeyFor() — valida mínimo 256 bits
  • Claims del token: subject (username), roles (lista), idioma, iat (emisión), exp (caducidad)
  • isTokenValid(): captura JwtException e IllegalArgumentException → devuelve false (no propaga)
  • parseClaims(): llama a verifyWith(secretKey) antes de leer el payload — la firma siempre se verifica

Endpoint de login (POST /api/v1/auth/login)

  • DTOs: LoginRequest record con @NotBlank, LoginResponse record (token, username, nombreCompleto, roles, idioma)
  • AuthService.login(): busca usuario → verifica BCrypt → genera JWT → devuelve LoginResponse
  • Principio de seguridad: mismo error "Credenciales incorrectas" si el usuario no existe o si la contraseña es incorrecta — evita user enumeration
  • AuthController: @PostMapping("/login"), @Valid @RequestBody, anotaciones @Operation + @ApiResponse
  • Probado desde Swagger UI: POST /api/v1/auth/login con credenciales válidas → 200 con JWT

Jueves 2026-06-18

✅ Completado

Implementación de JwtAuthenticationFilter

  • JwtAuthenticationFilter.java extiende OncePerRequestFilter — una sola ejecución por petición
  • Flujo del filtro:
  • Lee Authorization: Bearer <token> de la cabecera HTTP
  • Sin token o prefijo incorrecto → continúa sin autenticar (Spring Security denegará el acceso si la ruta es protegida)
  • Llama a jwtProvider.isTokenValid(token) — verifica firma y expiración
  • Si válido: extrae username y roles, construye UsernamePasswordAuthenticationToken (3 argumentos = autenticación completa)
  • Guarda el Authentication en SecurityContextHolder — ThreadLocal, seguro en multihilo
  • Roles → SimpleGrantedAuthority("ROLE_" + rol) (convenio de Spring Security para hasRole())
  • Registrado con addFilterBefore(..., UsernamePasswordAuthenticationFilter.class)

Endpoint protegido de prueba

  • PruebaController.java: GET /api/v1/prueba/protegido devuelve 200 con el username del usuario autenticado
  • Ruta no incluida en las rutas públicas → protegida por anyRequest().authenticated()

  • Sin token: GET /api/v1/prueba/protegido → 401 Unauthorized ✅
  • Con token válido: GET /api/v1/prueba/protegido → 200 OK ✅
